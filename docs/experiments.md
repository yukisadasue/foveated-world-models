# 実験計画

実験は未実施。データセット、計算予算、seed数、評価条件は実装前に固定する。GPU候補はRTX 6000とA100だが、世代・VRAM・台数は未確認であり、速度や学習時間を約束しない。

## Phase 0：基準とデータ

LaWAMの公開実装・重み・設定のコミットを固定し、推論と予測対象を確認する。最初は予測器単体を扱う。データは学習・検証・テストを軌跡単位で分け、同一動画の近隣フレーム漏洩を防ぐ。未見場面・物体・視点の分割も設ける。実世界動画とシミュレーションを区別して報告する。

## Phase 1：背景偏りの診断

比較は現在特徴のコピー、基準予測器、提案予測器。背景・物体・接触周辺それぞれの領域平均誤差と、全体損失への寄与を測る。領域面積、勾配寄与、予測時間幅別の結果も記録する。評価用の正解領域や物体状態は入力に流さない。

潜在行動の条件を分ける。

- 正解の前後画像から得た潜在行動：教師潜在による再構成・条件付き予測能力の診断。
- 現在までの情報から得た潜在行動：実運用に対応する予測能力。

教師潜在だけの改善を未来予測全体の改善としない。単一の記録未来だけが正解とは限らないため、多峰性や実行可能な別未来も失敗分析で区別する。

## Phase 2：構造比較

| 比較基準 | 切り分ける要因 |
|---|---|
| 一様な低解像度 | 基本性能と最低コスト |
| 一様な高解像度 | 解像度を上げるだけの効果 |
| ROI重み付き損失のみ | 構造変更が本当に必要か |
| 固定crop・ランダムcrop | 単なる追加局所入力の効果 |
| 同容量の通常Transformer | パラメータ増加の効果 |
| 適応中心視野＋周辺視野 | 選択的な計算配分の効果 |
| 提案から周辺・追跡・座標・記憶を個別除去 | 各機構の寄与 |

同じエンコーダ、データ、予測時間幅で比較する。計算量、パラメータ数、学習更新数は別々に記録し、可能な範囲で対応した比較を用意する。正解ROIを使うoracleは上限診断として別枠にする。

## Phase 3：頑健性と速度

静止カメラ、カメラ並進・回転、物体移動、両者の移動、遮蔽と再出現、照明変化、背景だけの変化を比較する。合成の2D変換と3Dカメラ移動を同一視しない。予測器単体および実行パイプライン全体の遅延を計測する。

## Phase 4：制御への有用性

有望な予測器をLaWAM型の方策へ統合し、まずLIBERO等で閉ループ評価する。行動expert固定での交換試験と、同じ適応予算で再学習する試験を区別する。特徴分布の変化で固定expertが失敗する可能性を記録する。

成功率、外乱後の回復、完了時間、複数の独立学習seedによるばらつきを報告。画素・特徴予測だけの改善と制御改善を混同しない。画像デコーダを付ける場合は可視化系の誤差も分離する。

## 進む・見直す判断

- 背景への偏りが確認できない：仮説を修正し、論文の前提にしない。
- 損失の重み付けだけで同等：複雑な視野構造を採用する根拠を見直す。
- ROI推定費用が節約を上回る：低頻度更新・追跡再利用などを測り直す。
- 予測は改善するが制御は改善しない：予測対象・指標と行動の関係を調べる。
- 未見視点で改善しない：カメラ頑健性の主張を外す。
